# 技术参考

## 架构

```
浏览器（GitHub Pages 上的 index.html）
   ├─ POST { action:"models", password } ───────────────┐
   ├─ POST { action:"title", password, text } ──────────┤
   │                                                    │
   │ POST { messages, model, password,                  │
   │        reasoningEffort, session_id, webSearch,     │
   │        webSearchMaxUses?, webSearchMaxResults?,    │
   │        maxCompletionTokens? }                      │
   ▼
Cloudflare Worker（服务名 ember-proxy，代码 worker/worker.js）
   │ 1. 校验访问密码（Secret ACCESS_PASSWORD），错就 401
   │ 2. models 动作：带 Secret 向 OpenRouter 拉模型目录并精简返回
   │ 3. title 动作：带 Secret 调 DeepSeek V4 Flash，关闭 thinking，返回自然短标题
   │ 4. 聊天：给 system + 当前问题前一条 + 当前问题打缓存标记（仅 Claude）
   │ 5. 加 Authorization，显式请求推理返回；联网使用 openrouter:web_search server tool
   │    同时转发图片、可选搜索限制、生成上限、session_id，stream:true
   ├───────────────────────────────► DeepSeek（仅生成会话短标题）
   ▼
OpenRouter（/api/v1/chat/completions）
   ▼
网页设置中选定的 OpenRouter 模型（默认 anthropic/claude-opus-4.6）
   │ SSE 流式返回，原样透传回浏览器逐字渲染
```

Worker 是唯一的服务端，没有数据库；多会话文字历史、每会话 `session_id`、当前模型、收藏和设置只存浏览器 localStorage，图片 Blob 存当前设备 IndexedDB。OpenRouter 与 DeepSeek 的 key 都只在 Worker Secrets；同一道访问密码门禁挡陌生人白嫖。架构原理和“为什么”详见 `docs/项目详情.md`。

## 部署

- **前端**：PR #3 已合入 `main`（`aaa0426`）。GitHub Pages 发布源目前仍指向 `codex/multi-conversation` 分支，待轩在 Settings → Pages 切回 `main`（切前两者内容一致，零风险）；切完线上长期从 `main` 发布。
- **Worker（日常自动）**：合入 `main` 后，涉及 `worker/**` 的 push 会由 GitHub Actions（`.github/workflows/deploy-worker.yml`）先跑 `node worker/cache.test.mjs` 再部署 Cloudflare。功能分支预览用 Actions → Deploy Worker → Run workflow 手动选择分支。
- **Worker（手动备胎，已验证可用）**：
  - 方式 A：Cloudflare 网页后台粘贴 `worker.js` 内容直接 Deploy。
  - 方式 B：`cd worker && npx wrangler deploy`。
  - 详细步骤见 `worker/README.md`。

## 绝对不能动（完整清单）

1. API key、访问密码只放 Cloudflare Secret（`OPENROUTER_API_KEY`、`DEEPSEEK_API_KEY`、`ACCESS_PASSWORD`），绝不进代码/文档。
2. Worker 的 `ALLOWED_ORIGIN`（worker.js 顶部）必须等于 GitHub Pages 域名，否则浏览器 CORS 拦截；换域名要同步改代码 + 重新部署。
3. 改 worker 后必须重新部署，本地改不影响线上（日常已自动化，见上方「部署」）。
4. 默认模型 slug 是 `anthropic/claude-opus-4.6`（点，不是横杠），OpenRouter 上没有 `claude-opus-4-6`；其它模型必须从 Worker 拉回的目录中选择，不手填。
5. 仓库已 public，commit 任何东西前确认不含 key/密码/隐私。
6. 动 `worker/` 里缓存逻辑前，复查 `cache_control` 断点位置——易变内容不能插进缓存段中间（否则命中率归零），细节参考全局记忆「提示词缓存剧本」。

## 经验教训（防重复踩坑）

- OpenRouter 模型 slug 用点不用横杠：`anthropic/claude-opus-4.6`。
- CORS 只在浏览器里生效，curl/脚本直连 Worker 能绕过，必须加密码校验。
- GitHub 免费版不给 private 仓库开 Pages（报 422），本项目因此改 public。
- 改提示词缓存断点前必读全局记忆「提示词缓存剧本」：动态内容绝不能插进缓存段中间。
